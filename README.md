# Mia — ИИ-ассистент строительной компании (сети связи)

Миа — локальный ассистент для Telegram, работающий на **локальной LLM через Ollama**.
Она общается с сотрудниками (ИТР и офис), **помнит всё**, что происходит в рабочих
чатах по объектам, и помогает находить и связывать информацию. Вся обработка идёт
локально — данные компании не покидают вашу машину.

> Статус: **Этап 1** — рабочий каркас + документы. Миа запоминает все сообщения,
> отвечает, когда к ней обращаются, принимает и разбирает документы (в т.ч. OCR сканов),
> ведёт реестр. Дальше по плану — тяжёлые агенты и RAG-связи, голосовые и сводки,
> реестр «есть / нет / ждём», конфигуратор с автообновлением.
> Внутренняя «Mia PM OS» (Дневники объектов, Health Score, Safe Tools) развивается
> параллельно — см. `Todo.md` и `architecture.md`.

## Возможности (Этап 0)

- Telegram-бот на локальной LLM (Ollama).
- **Постоянная память**: каждое сообщение сохраняется в SQLite и индексируется
  для смыслового поиска (ChromaDB + эмбеддинги `bge-m3`).
- **Кроссчатовая память**: Миа помнит, из какого чата/объекта пришла информация,
  но связывает сведения между чатами.
- **Уровни достоверности**: слова владельца и гендиректора = истина; остальное —
  «весьма вероятно».
- **Понимание времени** (МСК).
- Персона и справедник сотрудников — в редактируемых файлах.
- В личке отвечает всегда; в группах — по @упоминанию или reply.

## Возможности (Этап 1 — документы)

- Принимает документы (**docx, xlsx, xls, pdf**) молча: скачивает, извлекает текст,
  сохраняет в память. **Сканы (PDF/фото) распознаются через OCR** локальной
  vision-моделью Ollama (по запросу; нужно `ollama pull qwen2.5vl:7b`).
- Отвечает по содержимому файла на любой вопрос (reply на документ).
- **Сводка по запросу** (не спамит на каждый файл): «Миа, дай сводку по этому
  документу» (ответом на файл или по последнему присланному) — Миа формирует
  **xlsx-сводку** с полями (объект, шифр, тип, номер, дата, суммы/объёмы, статус,
  краткое содержание) и присылает файлом.
- **Накопительный реестр**: каждая сводка добавляет строку в общий
  `data/Реестр.xlsx` (близко к «Реестру документов по сопровождению СМР»).
  Запрос «дай реестр» — Миа пришлёт его.

## Требования

- Windows 11 (или Linux/macOS), Python 3.11+
- [Ollama](https://ollama.com) с установленными моделями:
  ```bash
  ollama pull qwen2.5:14b-instruct   # рабочая модель (текст, русский)
  ollama pull bge-m3                 # эмбеддинги для памяти
  ```
- Telegram-бот от [@BotFather](https://t.me/BotFather)

## Быстрый запуск (Windows)

Всё делается через один запуск: обновление кода, установка зависимостей и
открытие конфигуратора, из которого запускается бот.

1. Один раз: скопируйте `.env.example` в `.env`, впишите `BOT_TOKEN`.
2. Установите модели Ollama: `ollama pull qwen2.5:14b-instruct`, `ollama pull bge-m3`,
   и для OCR `ollama pull qwen2.5vl:7b`.
3. Запускайте:
   - **`Mia.vbs`** — тихий запуск **без окна консоли** (рекомендуется; можно
     сделать ярлык на рабочий стол).
   - **`Mia.bat`** — то же самое, но с видимым окном (удобно для диагностики).

Всё управление — обновления, зависимости, старт/стоп бота, смена моделей,
логи — в конфигураторе. Отдельных `.bat` для бота больше нет: бот запускается
из конфигуратора, а он следит, чтобы не запустилось два экземпляра сразу.

## Установка (вручную / Linux / macOS)

```bash
# 1. Зависимости
pip install -r requirements.txt

# 2. Конфигурация
cp .env.example .env          # Windows: copy .env.example .env
# затем впишите BOT_TOKEN и, при необходимости, модель/пути

# 3. Запуск
python run.py                 # бот
python run_configurator.py    # конфигуратор
```

## Конфигурация

Основные параметры — в `.env` (см. `.env.example`):

| Параметр | Описание |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота |
| `BOT_USERNAME` | @username бота (для реакции на упоминания) |
| `OLLAMA_BASE_URL` | Адрес Ollama (по умолчанию `http://localhost:11434`) |
| `LLM_MODEL` | Рабочая модель (например, `qwen2.5:14b-instruct`) |
| `EMBED_MODEL` | Модель эмбеддингов (`bge-m3`) |
| `DATA_DIR` | Папка данных (память, документы, логи) |
| `TIMEZONE` | Часовой пояс (`Europe/Moscow`) |

Справочник сотрудников — `config/employees.json` (можно свободно править:
добавлять/убирать людей, менять тон общения Мии, отмечать авторитетные источники).

## Конфигуратор (GUI)

Отдельное окно для управления Мией без правки файлов:

```bash
python run_configurator.py
```

Вкладки:
- **Управление** — запуск/остановка/перезапуск бота, статусы (бот, Ollama, версия).
- **Модели** — список моделей Ollama и смена рабочей модели **на лету**
  (без перезапуска; удобно ночью переключаться на тяжёлую vision-модель).
  Активная модель хранится в `data/runtime.json`, бот подхватывает её сам.
- **Обновления** — «Проверить обновления» и «Обновить сейчас» из GitHub
  (`git pull`/reset на ветку `UPDATE_BRANCH`), плюс автопроверка по расписанию.
  Бот автоматически перезапускается после установки.
- **Логи** — просмотр логов в реальном времени, экспорт в ZIP и **отправка на
  GitHub** (в ветку `mia-logs`) — чтобы разработчику было видно, как всё работает.

Автообновление требует установки через `git clone`. Отправка логов и файлов
на GitHub требует `GITHUB_TOKEN` (Personal Access Token, scope `repo`) в `.env`.

> На Windows Tkinter входит в стандартную поставку Python. На Linux может
> потребоваться пакет `python3-tk`.

## Структура проекта

```
config/            # настройки, runtime и справочник сотрудников
  settings.py
  runtime.py
  employees.json
mia/
  core/            # LLM-клиент, персона, время, логирование, сотрудники
  memory/          # SQLite (лог) + Chroma (семантика) + сервис памяти
  assistant/       # оркестрация ответа
  bot/             # Telegram: точка входа и обработчики
configurator/      # GUI: управление, модели, обновления, логи
  app.py
  updater.py
  process_manager.py
  log_sender.py
run.py             # запуск бота (headless)
run_configurator.py# запуск конфигуратора
Mia.bat            # единый запуск (Windows): обновить → зависимости → конфигуратор
Mia.vbs            # тихий запуск без окна консоли (рекомендуется)
```

## RAG через AnythingLLM (свободные вопросы по документам)

Точные числа из таблиц (итоги смет, метраж) считает наш код — надёжно и без
галлюцинаций. А свободные вопросы по всей базе документов («что у нас по объекту
Судаково», «что в этом договоре») можно отдать в **AnythingLLM** (RAG/агенты).

1. Установите AnythingLLM Desktop, выберите движок **Ollama**, создайте workspace.
2. В настройках включите Developer API и создайте ключ.
3. Заполните в `.env`: `ANYTHINGLLM_BASE_URL`, `ANYTHINGLLM_API_KEY`, `ANYTHINGLLM_WORKSPACE`.

Тогда входящие документы автоматически добавляются в базу AnythingLLM, а общие
вопросы по документам идут через его RAG. Если не настроено — бот работает на
собственной памяти. Статус подключения виден в конфигураторе (строка «RAG»).

## Данные и приватность

Всё хранится локально в `DATA_DIR` (по умолчанию `./data`, для Windows удобно
`C:\Mia\data`): база сообщений, векторная память, документы, логи. Папка не
попадает в git. Наружу ничего не уходит.

## План развития

- **Этап 1** — приём и разбор документов (docx/xlsx/xls/pdf), сводка в xlsx,
  OCR сканов через vision-модель. ✅ Дальше: dwg.
- **Этап 2** — «тяжёлые» агенты и RAG (AnythingLLM как инструмент), связи и сводки.
- **Этап 3** — понимание времени как reminder + фоновая проактивность, STT (голосовые).
- **Этап 4** — реестр документов «есть / нет / ждём».
- **Этап 5** — конфигуратор с GUI: логи, смена моделей на лету (в т.ч. ночная
  тяжёлая vision-модель), автообновление из GitHub, отправка логов.
- Позже — Gmail, Google Drive, выгрузка на удалённый сервер и раскладка в NAS.
